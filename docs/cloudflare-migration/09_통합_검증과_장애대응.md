# 09. 통합 검증과 장애 대응

## 1. 검증 원칙

아래에서 위로 계층별로 검증한다.

```text
로컬 데이터
  -> DB/OpenSearch
  -> FastAPI
  -> worker local WebSocket
  -> R2 presigned PUT/GET
  -> cloudflared/Tunnel
  -> Access/CORS
  -> Pages frontend
  -> 검색/simulation 전체 흐름
```

상위 계층부터 테스트하면 CORS, Tunnel, API, worker 오류를 구분하기 어렵다.

## 2. 로컬 인프라 검증

```bash
cd ~/workspace/tradar
docker compose ps
docker compose -f docker-compose.desktop.yml ps
```

PostgreSQL:

```bash
docker compose exec -T db \
  psql -U postgres -d tradar -c 'select 1;'
```

OpenSearch:

```bash
curl -fsS http://127.0.0.1:9200/_cluster/health?pretty
curl -fsS 'http://127.0.0.1:9200/_cat/indices?v'
```

FastAPI:

```bash
curl -fsS http://127.0.0.1:8000/health
```

기대:

- DB query 성공
- OpenSearch cluster 최소 yellow/green, 주요 index 존재
- API `{"status":"ok"}`

## 3. Worker 검증

```bash
docker compose -f docker-compose.desktop.yml logs --tail=200 desktop-worker
```

확인:

- `WORKER_WS_URL=ws://api:8000/ws/worker`
- PostgreSQL connectivity OK
- OpenSearch connectivity OK
- Worker registered
- 반복적인 reconnect loop 없음

API logs:

```bash
docker compose logs --tail=200 api | grep -i worker
```

Worker token 오류는 보안을 위해 WebSocket close code만 보일 수 있다. Backend/worker 양쪽 token 값을 실제 출력하지 않고 길이/hash로 비교한다.

예시:

```bash
python - <<'PY'
import os, hashlib
for k in ("DESKTOP_WORKER_TOKEN", "WORKER_TOKEN"):
    v = os.getenv(k, "")
    print(k, len(v), hashlib.sha256(v.encode()).hexdigest()[:8] if v else "MISSING")
PY
```

Container별 env가 다르므로 실제 비교는 각 container 안에서 수행한다.

## 4. R2 검증

### Backend presign

```bash
curl -fsS -X POST http://127.0.0.1:8000/media/presign \
  -H 'Content-Type: application/json' \
  -d '{"filename":"integration-test.png","content_type":"image/png"}'
```

### Upload와 read

[04 R2 문서](./04_R2_오브젝트_스토리지.md)의 PUT/GET 절차를 실행한다.

확인:

- URL host가 AWS S3가 아니라 R2 S3 API endpoint
- PUT 200
- GET/HEAD 200
- R2 dashboard에 `queries/YYYY/MM/DD/...` object 생성
- TTL 만료 후 접근 거절

### Browser CORS

Pages frontend에서 실제 이미지를 선택한다. Browser Network:

```text
POST https://api.example.com/media/presign
OPTIONS/PUT https://<account>.r2.cloudflarestorage.com/...
POST https://api.example.com/search/multimodal
```

R2 PUT의 request `Content-Type`과 presign response `content_type`을 비교한다.

## 5. Tunnel/Access 검증

비인증:

```bash
curl -i https://api.example.com/health
```

기대:

- Access login redirect/403
- FastAPI JSON이 직접 공개되지 않음

허용 브라우저:

1. `https://tradar.example.com` 접속
2. Access 로그인
3. 새 tab에서 `https://api.example.com/health`
4. JSON 확인

Preflight:

```bash
curl -i -X OPTIONS https://api.example.com/search/multimodal \
  -H 'Origin: https://tradar.example.com' \
  -H 'Access-Control-Request-Method: POST' \
  -H 'Access-Control-Request-Headers: content-type,x-client-id'
```

## 6. Pages 검증

```bash
curl -I https://tradar.example.com
```

Access login 후 Browser Network에서:

- index/JS/CSS 200
- Console error 없음
- API base가 `https://api.example.com`
- AWS CloudFront/S3/ECS URL 요청 없음
- API request에 cookie 포함
- API response content type JSON

## 7. 검색 end-to-end 검증

### 이미지 + 텍스트 검색

1. 작은 PNG/JPEG 선택
2. 검색 텍스트 입력
3. R2 upload 확인
4. `/search/multimodal` 요청 확인
5. API가 worker에 job dispatch
6. worker가 R2 GET
7. DB/OpenSearch 검색
8. 결과가 frontend에 표시

확인 결과:

- image top/misc
- text top/misc
- thumbnail/image 표시
- class/status/goods metadata
- 오류 message가 HTML Access 페이지가 아님

### 텍스트 중심 검색

- 빈 이미지/허용 흐름 확인
- 한글/영어 query
- class/group filter
- LLM variants on/off

### Worker 없음

```bash
docker compose -f docker-compose.desktop.yml stop desktop-worker
```

검색 요청은 503과 명확한 메시지를 반환해야 한다. 이후 worker 재시작:

```bash
docker compose -f docker-compose.desktop.yml start desktop-worker
```

자동 재등록 후 검색이 복구되는지 확인한다.

## 8. Goods search 검증

```bash
curl -fsS --get http://127.0.0.1:8000/goods/search \
  --data-urlencode 'q=소프트웨어' \
  --data-urlencode 'lang=ko'
```

Tunnel/Pages에서도 같은 기능을 확인한다. 이 endpoint는 API가 PostgreSQL에 직접 접근하므로 worker 검색 성공과 별도로 검증해야 한다.

## 9. Simulation 검증

전체 흐름:

1. 검색 완료 및 `search_id` 생성
2. 후보 선택
3. `POST /simulation/run`
4. `GET /simulation/stream/{job_id}` EventSource 연결
5. progress update
6. complete/cancel/error

Browser Network에서 SSE 확인:

```text
Status: 200
Content-Type: text/event-stream
Connection remains open
Event data arrives
```

Access login HTML이나 302가 stream 응답에 섞이면 EventSource credentials/Access cookie를 확인한다.

API 재시작 시 simulation job state는 메모리에서 사라진다. 현재 구조에서는 정상적인 제한이다. 배포/재시작 전에 실행 중 job이 없는지 확인한다.

## 10. Admin 검증

- `/admin`이 Access 보호 아래 있음
- application admin login도 추가로 필요
- 잘못된 password 거절
- cookie secret 설정
- admin 페이지에서 secret/환경변수 노출 없음

## 11. 재부팅 복구 테스트

실제 운영 전 최소 한 번 데스크톱을 재부팅한다.

재부팅 후:

```bash
systemctl is-active docker
docker compose ps
docker compose -f docker-compose.desktop.yml ps
```

검증 순서:

1. DB healthy
2. OpenSearch healthy
3. API health
4. worker registered
5. cloudflared healthy
6. Pages에서 검색

Desktop sleep/hibernate가 예정되어 있으면 서비스 시간 동안 비활성화한다.

## 12. 장애 주입 테스트

### cloudflared restart

```bash
docker compose restart cloudflared
```

Connector 자동 복구와 API 접근 복구 시간을 기록한다.

### API restart

```bash
docker compose restart api
```

Worker가 exponential backoff로 자동 reconnect하는지 확인한다.

### OpenSearch stop

```bash
docker compose stop opensearch
```

Worker/API 오류가 무한 hang하지 않는지 확인 후 즉시 복구한다.

```bash
docker compose start opensearch
```

### R2 credential 오류

운영 credential을 직접 훼손하지 말고 별도 테스트 env에서 잘못된 key로 presign/upload error가 명확한지 확인한다.

## 13. 로그 수집

```bash
docker compose logs --since=30m api cloudflared > /tmp/tradar-api-tunnel.log
docker compose -f docker-compose.desktop.yml logs --since=30m desktop-worker \
  > /tmp/tradar-worker.log
```

공유 전 제거할 값:

- presigned query string
- API key/token
- DB URL password
- Access cookie/JWT
- 사용자 이미지/개인정보

## 14. 장애별 판단표

| 사용자 현상 | 우선 확인 | 다음 확인 |
|---|---|---|
| Frontend 자체 안 열림 | Pages deployment/Access | DNS |
| API 502 | API container | Tunnel origin/network |
| API 403/302 | Access cookie/policy | frontend credentials |
| CORS error | Access OPTIONS | FastAPI CORS, R2 CORS |
| Upload만 실패 | R2 CORS/Content-Type | token/endpoint |
| Search 503 | worker 등록 | token/network |
| Search timeout | worker logs | DB/OpenSearch/GPU |
| Goods만 실패 | PostgreSQL | API DB URL |
| Simulation stream 실패 | EventSource credentials | API state/SSE headers |
| 이미지 결과만 깨짐 | local path/media root | R2 GET/thumbnail ref |
