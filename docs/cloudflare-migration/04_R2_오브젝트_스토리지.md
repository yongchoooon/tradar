# 04. Cloudflare R2 오브젝트 스토리지 구성

## 1. R2 사용 범위

R2에 저장할 데이터:

- 브라우저가 업로드한 검색 질의 이미지
- presigned GET URL로 worker가 읽을 임시 이미지
- 현재 `app/services/log_storage.py`가 올리는 검색/사용 로그
- 선택적 PostgreSQL dump/원본 데이터 백업

R2로 옮기지 않을 라이브 데이터:

- PostgreSQL/pgvector
- OpenSearch index
- MetaCLIP/DINO 모델
- `~/workspace/tradar-data` 원본 이미지

원본 상표 데이터는 worker가 로컬 볼륨에서 읽는 구조를 유지한다.

## 2. Bucket 설계

최소 변경 구성:

```text
tradar-uploads
  queries/YYYY/MM/DD/<uuid>.<ext>
  logs/...
```

운영 분리 구성:

```text
tradar-uploads   브라우저 질의 이미지
tradar-logs      검색/시뮬레이션 로그
tradar-backups   DB/원본 데이터 백업
```

초기 전환은 한 bucket으로 시작할 수 있지만 retention, 권한, 비용을 독립 관리하려면 분리를 권장한다.

설정:

```text
Storage class: Standard
Public access: Disabled
```

Presigned URL을 사용하므로 bucket을 public으로 만들 필요가 없다.

## 3. R2 S3 API token

R2 dashboard에서 S3 API token을 생성한다.

Upload bucket token:

```text
Scope: 특정 tradar-uploads bucket
Permissions: Object Read + Object Write
```

Backup token이 필요하면 별도로 만든다.

```text
Scope: tradar-backups
Permissions: backup 도구에 필요한 최소 권한
```

저장할 값:

```text
Account ID
Access Key ID
Secret Access Key
Endpoint: https://<ACCOUNT_ID>.r2.cloudflarestorage.com
Region: auto
```

Cloudflare global API key를 boto3에 사용하지 않는다.

## 4. R2 CORS

브라우저가 FastAPI가 발급한 URL로 R2에 직접 PUT하므로 R2 bucket에 CORS가 필요하다.

```json
[
  {
    "AllowedOrigins": [
      "https://tradar.example.com",
      "http://localhost:5173"
    ],
    "AllowedMethods": [
      "GET",
      "PUT",
      "HEAD"
    ],
    "AllowedHeaders": [
      "Content-Type"
    ],
    "ExposeHeaders": [
      "ETag"
    ],
    "MaxAgeSeconds": 3600
  }
]
```

운영 완료 후 localhost origin을 제거한다.

주의:

- Presigned URL이 유효해도 CORS가 없으면 브라우저 PUT이 실패할 수 있다.
- Presign에 `ContentType`을 포함했다면 실제 PUT의 `Content-Type`이 정확히 같아야 한다.
- `AllowedOrigins: ["*"]`를 운영에 사용하지 않는다.

## 5. 백엔드 환경변수

AWS용 credential chain을 사용하지 않는다. `app/services/r2_client.py`가 다음 **R2 전용 변수**를 명시적으로 읽는다.

```env
R2_ENABLED=true
R2_BUCKET=tradar-data
R2_LOG_BUCKET=tradar-data
R2_ENDPOINT_URL=https://<ACCOUNT_ID>.r2.cloudflarestorage.com
R2_ACCESS_KEY_ID=<R2_ACCESS_KEY_ID>
R2_SECRET_ACCESS_KEY=<R2_SECRET_ACCESS_KEY>
R2_REGION=auto
R2_IMAGE_PREFIX=queries
R2_LOG_PREFIX=logs
R2_PRESIGN_TTL_SECONDS=600
R2_LOGS_ENABLED=true
R2_UPLOAD_OPENAI_USAGE=true
ALLOW_BASE64_FALLBACK=false
```

실제 이름과 전체 목록은 `.env.runtime.example`을 기준으로 한다. R2 API token은 브라우저나 Pages build에 넣지 않고 API/worker 컨테이너에만 주입한다.

## 6. Backend/worker의 R2 사용

API와 worker는 현재 같은 `.env.runtime`을 사용한다. 따라서 다음 한 쌍의 bucket-scoped token으로 시작한다.

```text
R2_ACCESS_KEY_ID
R2_SECRET_ACCESS_KEY
```

코드는 AWS의 credential 환경변수, SSM 또는 EC2/ECS metadata credential을 fallback으로 읽지 않는다. Token은 해당 bucket의 Object Read & Write로 제한한다. 로그를 별도 bucket/token으로 완전히 분리하려면 이후 client factory를 다중 credential로 확장해야 하며, 현재 단계에서는 `R2_LOG_BUCKET`만 분리할 수 있다.

## 7. 로컬 연결 검증

Secret을 shell history에 입력하지 않는다.

```bash
cp .env.runtime.example .env.runtime
chmod 600 .env.runtime
# 편집기로 CHANGE_ME를 모두 교체
```

레포에 포함된 검증 script를 실행한다.

```bash
.venv/bin/python scripts/verify_r2.py --env-file .env.runtime
.venv/bin/python scripts/verify_r2.py --env-file .env.runtime --write
```

첫 명령은 bucket list 권한을 확인하고, 두 번째는 `_healthchecks/` 아래 작은 object를 PUT/GET/DELETE한다. Script는 credential 자체를 출력하지 않는다.

## 8. FastAPI presign 검증

```bash
curl -fsS -X POST http://127.0.0.1:8000/media/presign \
  -H 'Content-Type: application/json' \
  -d '{"filename":"r2-test.png","content_type":"image/png"}' \
  > /tmp/tradar-r2-presign.json

python -m json.tool /tmp/tradar-r2-presign.json
```

URL 추출:

```bash
UPLOAD_URL=$(python -c 'import json; print(json.load(open("/tmp/tradar-r2-presign.json"))["upload_url"])')
READ_URL=$(python -c 'import json; print(json.load(open("/tmp/tradar-r2-presign.json"))["read_url"])')
```

PUT/GET:

```bash
curl -i -X PUT "$UPLOAD_URL" \
  -H 'Content-Type: image/png' \
  --data-binary @/path/to/test.png

curl -I "$READ_URL"
```

브라우저 CORS 검증은 Pages origin에서 수행한다. curl 성공만으로 브라우저 CORS 성공을 보장하지 않는다.

## 9. Presigned URL 보안

- Presigned URL은 만료 전까지 bearer token처럼 취급한다.
- URL을 application log에 전체 문자열로 남기지 않는다.
- TTL은 현재 기본 600초를 유지한다.
- 파일 확장자만 믿지 말고 content type/실제 이미지 검증을 유지한다.
- upload key는 UUID를 사용하여 사용자가 임의 경로를 선택하지 못하게 한다.
- bucket credential은 브라우저로 내려보내지 않는다.

## 10. 기존 S3 데이터 이전

서비스 중단 허용 전략에서는 AWS S3를 삭제하기 전에 필요한 object를 로컬로 내려받은 뒤 R2로 올리는 방식이 단순하다.

### AWS S3 -> 로컬

```bash
aws s3 sync s3://<source-bucket> "$HOME/tradar-s3-backup/<source-bucket>"
```

### 로컬 -> R2

AWS CLI/boto3에 R2 endpoint를 지정한다.

```bash
aws s3 sync \
  "$HOME/tradar-s3-backup/<source-bucket>" \
  s3://tradar-uploads/<optional-prefix> \
  --endpoint-url "https://<ACCOUNT_ID>.r2.cloudflarestorage.com" \
  --region auto
```

AWS credential과 R2 credential이 동시에 필요하면 profile을 분리한다.

```bash
AWS_PROFILE=source-aws aws s3 sync s3://<source-bucket> /tmp/source
AWS_PROFILE=cloudflare-r2 aws s3 sync /tmp/source s3://tradar-uploads \
  --endpoint-url "https://<ACCOUNT_ID>.r2.cloudflarestorage.com"
```

검증:

- source/target object 수
- 총 바이트
- 일부 표본 checksum
- application GET

S3 version history 자체는 `sync`로 이전되지 않는다. 현재 version만 보존할지 과거 version까지 보존할지 삭제 전에 결정한다.

## 11. Lifecycle/retention

질의 이미지는 영구 보존이 필요하지 않다면 retention을 정한다.

예시 정책:

```text
queries/: 7일 또는 30일 후 삭제
logs/: 연구/감사 요구에 따라 90일 또는 장기 보존
backups/: 월별 보존 정책과 최소 복구 세대 유지
```

검색 응답/시뮬레이션이 만료된 질의 이미지를 나중에 다시 읽어야 하는지 확인한 뒤 lifecycle을 설정한다.

## 12. 비용과 사용량

R2는 저장 용량과 Class A/B operation을 기준으로 사용량을 관리한다. egress 특성만 보고 무제한 무료라고 가정하지 않는다.

모니터링:

- bucket storage
- PUT 수
- GET/HEAD 수
- 실패/거부 요청
- 오래된 query object
- 로그 증가율

## 13. 문제 해결

| 현상 | 원인 후보 | 확인 |
|---|---|---|
| `SignatureDoesNotMatch` | Content-Type 차이, endpoint/region 오류 | presign과 PUT header 비교, region `auto` |
| `AccessDenied` | token bucket/permission 오류 | token scope 확인 |
| curl 성공, 브라우저 실패 | R2 CORS | origin/method/header 확인 |
| GET URL 만료 | TTL 경과 | 새 presign 생성 |
| worker fetch 실패 | worker DNS/인터넷 또는 URL 만료 | worker container에서 curl |
| boto3가 AWS로 접속 | endpoint env 누락 | `R2_ENDPOINT_URL` 확인 |

## 14. 완료 조건

- [ ] Private R2 bucket을 만들었다.
- [ ] Bucket 최소 권한 token을 만들었다.
- [ ] Pages/local origin CORS를 설정했다.
- [ ] Backend가 R2 endpoint로 presign한다.
- [ ] Browser PUT과 worker GET이 성공한다.
- [ ] Secret이 frontend/Git에 없다.
- [ ] 기존 S3 보존 데이터 이전을 검증했다.
- [ ] query/log retention을 결정했다.
