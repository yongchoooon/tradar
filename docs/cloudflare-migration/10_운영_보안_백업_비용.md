# 10. 운영·보안·백업·비용 관리

## 1. 운영 책임 범위

AWS ECS를 제거하면 다음 운영 책임이 데스크톱으로 이동한다.

- 전원/인터넷
- Docker daemon
- 디스크 용량
- PostgreSQL backup
- OpenSearch 상태
- GPU/driver
- OS 보안 업데이트
- cloudflared 업데이트
- API/worker 자동 재시작

Pages/R2/Tunnel이 정상이어도 데스크톱이 꺼지면 동적 기능은 중단된다.

## 2. Secret 분류

### Backend/worker 전용

- R2 access/secret key
- OpenAI/Gemini/KIPRIS key
- Hugging Face token
- PostgreSQL password/URL
- admin password/cookie secret
- worker shared token
- Tunnel token

### Frontend 공개 가능

```text
VITE_API_BASE_URL=https://api.example.com
```

Vite 환경변수는 bundle에 들어가므로 `VITE_` prefix로 secret을 만들지 않는다.

## 3. Secret 저장

최소 구성:

- Git에서 무시된 `.env.runtime`
- Git에서 무시된 `.env.cloudflare`
- file mode 600
- 암호화된 외부 백업

```bash
chmod 600 .env.runtime .env.cloudflare
```

권장 구성:

- 1Password/Doppler/SOPS/age 같은 secret 관리
- Docker secret
- 사용자별 최소 권한
- rotation 기록

SSM export JSON은 migration 완료 후 그대로 방치하지 않는다. 새 저장소 이전과 검증 후 암호화 또는 안전 삭제한다.

## 4. Token 분리

가능하면 다음을 분리한다.

- Backend upload R2 token
- Worker log R2 token
- Backup R2 token
- Cloudflare dashboard automation token
- Tunnel connector token

하나가 유출되어도 전체 bucket/account를 제어하지 못하게 bucket scope와 권한을 제한한다.

## 5. Rotation

전환 완료 직후 rotation 권장:

- 기존 AWS GitHub access key: 삭제
- ECS에서 사용했던 worker token: 새 값으로 교체 가능
- admin cookie secret: 사용 중 session 무효화 감수 후 교체
- SSM export 과정에서 다뤄진 high-value API key: 필요 시 교체

유출/의심 시 즉시:

1. Credential revoke
2. 새 credential 발급
3. env 교체
4. container recreate
5. 로그/사용량 확인

## 6. PostgreSQL backup

권장 최소:

```text
매일 dump
최근 7일 daily
최근 4주 weekly
최근 6~12개월 monthly
```

Backup은 같은 디스크에만 두지 않는다.

검증:

- dump 생성 성공
- 파일 크기 비정상 감소 감지
- checksum
- 정기 restore test
- encryption

Cron/systemd timer를 사용하되 실패 알림을 만든다.

## 7. OpenSearch backup/rebuild

OpenSearch를 PostgreSQL/원본 데이터에서 재생성할 수 있다면 다음을 보존한다.

- OpenSearch image/version
- index mapping/settings
- index 이름
- `scripts/sync_opensearch.sh`
- 재생성 소요 시간

재생성 불가능한 데이터가 있으면 snapshot을 별도 보관한다.

## 8. 원본 데이터 backup

`~/workspace/tradar-data`는 최소 두 개의 독립 매체/위치에 둔다.

예:

```text
라이브 SSD
외장 디스크 backup
선택적 encrypted R2 backup
```

R2 backup을 live object serving 경로와 같은 token/bucket으로 섞지 않는다.

## 9. R2 lifecycle

예시:

```text
queries/: 7~30일
logs/: 90일 또는 연구 요구 기간
backups/: 세대별 retention
```

Lifecycle 삭제 전에 simulation/report가 오래된 query image URL에 의존하는지 확인한다.

## 10. 로그 정책

수집:

- API access/error
- worker connect/job/error
- cloudflared connector
- PostgreSQL backup 결과
- OpenSearch health
- R2 upload failure

금지:

- API key
- DB password가 포함된 URL
- `CF_Authorization`
- worker token
- 전체 presigned URL query
- 불필요한 사용자 이미지

Docker json log가 디스크를 채우지 않도록 rotation을 설정한다.

예시 Docker daemon 또는 service log option:

```yaml
logging:
  driver: json-file
  options:
    max-size: "20m"
    max-file: "5"
```

## 11. 모니터링

최소 확인 항목:

```text
Desktop online
Docker daemon active
API /health
Worker registered/readiness
PostgreSQL backup freshness
OpenSearch cluster health
Disk usage
GPU availability
Tunnel connector health
R2 usage/errors
Pages latest deployment
```

간단한 외부 uptime monitor는 Access 인증 때문에 `/health`를 직접 호출하기 어렵다. 공개 health endpoint를 만들기보다 Access service token 또는 Cloudflare dashboard connector alert를 검토한다.

## 12. 디스크 관리

```bash
df -h
docker system df
du -sh ~/workspace/tradar-data
docker volume ls
```

`docker system prune -a --volumes`는 DB/OpenSearch volume 삭제 위험이 있으므로 자동/무검토 실행하지 않는다.

정리 대상:

- 오래된 build cache
- dangling image
- rotated log
- 만료된 local backup

DB/OpenSearch named volume은 명시적으로 보존한다.

## 13. 데스크톱 보안

- OS/브라우저/Docker 정기 업데이트
- SSH 필요 시 key-only 및 방화벽
- 5432/9200/8000 공인 노출 금지
- 공유기 port forwarding 금지
- 로컬 사용자 계정 password/MFA
- full-disk encryption
- 자동 화면 잠금
- backup encryption
- 사용하지 않는 서비스 종료

## 14. Cloudflare 보안

- Account MFA
- 최소 권한 API token
- Access 이메일 allowlist
- OPTIONS만 CORS bypass
- API rate limit
- Tunnel token rotation 절차
- Pages default domain 우회 여부 점검
- R2 bucket public access off

## 15. 비용 관리

### Cloudflare

확인:

- R2 저장 용량
- Class A/B operation
- Pages build 수
- Workers/Access 유료 기능 사용 여부
- rate limiting plan

R2의 egress 특성만 보고 비용이 항상 0이라고 가정하지 않는다.

### AWS

삭제 후 다음 날과 다음 청구서에서 확인한다.

- NAT Gateway
- ALB
- Elastic IP
- S3 noncurrent version
- Route 53 hosted zone/domain
- CloudWatch logs
- Marketplace/Support

## 16. 업데이트 절차

### Application

1. Git branch에서 코드 변경
2. pytest/frontend build
3. 로컬 API/worker image build
4. 실행 중 simulation 없음 확인
5. API/worker 순차 recreate
6. readiness/검색 검증
7. main merge로 Pages 배포

### cloudflared

1. 새 version release note 확인
2. 명시 version으로 test
3. connector recreate
4. Tunnel/Access/SSE 검증

### PostgreSQL/OpenSearch

Major upgrade 전 backup/restore test를 완료한다. OpenSearch mapping/index compatibility를 확인한다.

## 17. Incident runbook

### 데스크톱 장애

1. 전원/인터넷 확인
2. Docker daemon 확인
3. disk full 확인
4. DB/OpenSearch/API/worker/cloudflared 순서 확인
5. 데이터 volume을 삭제하지 않고 복구

### Credential 유출

1. 해당 token revoke
2. Access/log에서 사용 확인
3. 새 token 발급
4. env와 container 교체
5. 범위가 넓으면 연관 secret도 rotation

### DB 손상

1. 추가 write 중지
2. volume snapshot/copy
3. 최신 정상 dump 확인
4. 별도 DB에 restore
5. 검증 후 service 전환

### R2 장애

1. Cloudflare status/token/usage 확인
2. 신규 upload 일시 중단
3. 기존 로컬 corpus 검색 영향 구분
4. 복구 후 presign PUT/GET 재검증
