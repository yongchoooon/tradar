# 08. 애플리케이션 코드 변경 현황

> 이 문서는 계획안이 아니라 현재 `main` 작업 트리에 반영한 변경을 설명한다. Dashboard 값과 실제 secret 입력은 아직 사용자 작업이다.

## 1. 완료한 코드 변경

| 영역 | 변경 파일 | 상태 |
|---|---|---|
| R2 client | `app/services/r2_client.py` | R2 전용 endpoint/region/credential을 명시적으로 사용 |
| 이미지 전송 | `app/services/r2_storage.py` | 실제 이미지 검증, presigned PUT/GET, TTL 제한, worker URL host 검증 |
| API route | `app/api/routes_media.py` | S3 명칭을 R2로 변경, 설정/업로드 오류 분리 |
| 로그 | `app/services/log_storage.py` | R2 bucket/prefix 사용 |
| Worker bridge | `app/services/worker_bridge.py`, `worker/main.py` | R2 URL을 worker 전달 전과 download 전에 검증 |
| AWS 설정 | `app/services/ssm_params.py` | 삭제, runtime env-only로 변경 |
| Frontend 인증 | `frontend/src/lib/apiClient.ts` | API fetch에 `credentials: 'include'` |
| SSE 인증 | `frontend/src/App.jsx` | `EventSource(..., {withCredentials: true})` |
| Proxy client IP | `app/main.py` | `CF-Connecting-IP` 우선 |
| Docker | `docker-compose*.yml` | 로컬 bind, healthcheck, restart, cloudflared, 로컬 worker WebSocket |
| CI/CD | `.github/workflows/*.yml` | AWS workflow 제거, CI와 Pages Direct Upload workflow 추가 |

## 2. R2 환경변수

기준 template은 `.env.runtime.example`이다.

```env
R2_ENABLED=true
R2_BUCKET=tradar-data
R2_LOG_BUCKET=tradar-data
R2_ENDPOINT_URL=https://<ACCOUNT_ID>.r2.cloudflarestorage.com
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_REGION=auto
R2_IMAGE_PREFIX=queries
R2_LOG_PREFIX=logs
R2_PRESIGN_TTL_SECONDS=600
R2_LOGS_ENABLED=true
ALLOW_BASE64_FALLBACK=false
```

AWS 이름의 credential이나 SSM fallback은 사용하지 않는다. Presigned URL은 `https`이며 설정한 R2 endpoint host와 일치하는지 검증한다. URL 전체를 로그에 남기지 않는다.

## 3. Frontend와 Cloudflare Access

Frontend API 요청은 Access authorization cookie를 보낼 수 있도록 credentials mode를 `include`로 설정했다. Simulation SSE도 `withCredentials`를 사용한다.

반대로 R2 presigned PUT은 URL 자체가 제한된 bearer credential이므로 다음을 추가하지 않는다.

- Cloudflare Access header/cookie
- R2 access key/secret
- 별도 Authorization header

Frontend와 API가 다른 hostname이면 Access에서 두 구체적인 hostname을 한 multi-domain application에 포함하는 구성을 권장한다. 그렇지 않으면 API hostname에서 별도 인증이 필요하거나 브라우저의 third-party-cookie 정책에 영향을 받을 수 있다.

## 4. SSM 제거

다음은 완료됐다.

- `app/services/ssm_params.py` 삭제
- `app/services/worker_settings.py` env-only 변경
- ECS task role/SSM parameter 경로 의존 제거

따라서 `TRADAR_DISABLE_SSM` flag는 없다. 모든 secret은 Git에서 무시되는 `.env.runtime`에 넣고, 이전 대화/문서에 노출한 키는 재사용하지 않는다.

## 5. Compose 변경

API/DB/OpenSearch host port는 `127.0.0.1`에만 bind된다. 외부 공유기 port forwarding은 필요 없다.

```text
Browser -> Cloudflare Tunnel -> cloudflared -> http://api:8000
Worker  -> Docker network -> ws://api:8000/ws/worker
```

Cloudflared는 `.env.cloudflare`의 `TUNNEL_TOKEN`을 읽는다. 이 token은 command argument나 GitHub Pages secret으로 전달하지 않는다.

API는 worker registry와 simulation 상태를 process memory에 보관하므로 현재는 API replica 1개/Uvicorn worker 1개를 유지한다.

## 6. GitHub Actions 변경

삭제:

```text
.github/workflows/frontend-deploy.yml
.github/workflows/backend-deploy.yml
ecs/task-definition.json
```

추가:

```text
.github/workflows/ci.yml
.github/workflows/cloudflare-pages-deploy.yml
```

Pages workflow는 `main`의 frontend 변경을 Node 22로 build하고 Wrangler Action으로 Direct Upload한다. 다음 GitHub 설정은 사용자가 실제 Cloudflare 값을 만든 뒤 입력한다.

```text
Secrets:  CLOUDFLARE_API_TOKEN, CLOUDFLARE_ACCOUNT_ID
Variables: CLOUDFLARE_PAGES_PROJECT, VITE_API_BASE_URL
```

## 7. 추가 코드 수정이 필요한 시점

현재 migration 기본 구현에는 추가 provider 교체 코드가 필요하지 않다. 아래 경우에는 후속 코드 수정이 필요하다.

1. **Frontend/API를 같은 origin으로 합칠 때**: Pages Functions/Worker proxy와 route 변경
2. **API를 여러 replica로 늘릴 때**: worker registry, search cache, simulation jobs를 Redis/DB 같은 외부 상태로 이전
3. **로그 bucket에 별도 token을 쓸 때**: R2 client를 용도별 credential factory로 확장
4. **운영 readiness가 필요할 때**: DB/OpenSearch/worker 연결을 확인하는 `/ready` endpoint 추가
5. **PR Preview를 production API에 연결할 때**: dynamic CORS/Access 설계를 먼저 추가

Dashboard hostname, DNS, R2 CORS, Access policy 입력은 설정 작업이며 코드 수정이 아니다.

## 8. 검증 명령

```bash
cd ~/workspace/tradar
.venv/bin/pytest -q
.venv/bin/python -m compileall -q app worker scripts/verify_r2.py

docker compose --env-file .env.runtime config >/dev/null

cd frontend
npm ci
VITE_API_BASE_URL=https://api.example.com npm run build
npm audit
```

실제 R2 credential을 채운 뒤:

```bash
.venv/bin/python scripts/verify_r2.py --env-file .env.runtime --write
```
